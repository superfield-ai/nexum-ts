## Claim

The graph's typed links enable attribution — tracing exactly which blocks contributed to a generated answer — with < 5% false attribution rate, something structurally impossible for dense transformer weights.

## Operationalization

Dataset: 200 Q&A pairs with known ground-truth source blocks (human-labeled).
Metric: false attribution rate (attributed blocks not in ground-truth set / total attributed blocks).
Baseline: n/a (static dense models cannot produce block-level attribution by definition).
Intervention: graph-resident inference client; for each answer, collect the set of retrieved blocks that contributed to the generation via `nxm_provenance_agg` (or equivalent provenance trace).
Acceptance criterion: false attribution rate < 5% on the labeled eval set.

## Null Hypothesis

The retrieval step surfaces many irrelevant blocks that technically contributed to the generation context but did not causally determine the answer; false attribution rate exceeds 5%, making provenance claims misleading.

## Experiment Spec

1. Build a 200-question eval set over the legal corpus. For each question, have a domain expert label the 1–3 blocks that contain the answer.
2. Run graph-resident inference. For each question, collect all blocks retrieved across inference steps.
3. Compare retrieved block set to ground-truth set. Compute false attribution rate.
4. Compute recall (ground-truth blocks found in retrieved set).
5. Report both metrics. A good provenance system needs high recall AND low false attribution simultaneously.

## Results

**G2 wedge run (issue #9, 2026-05-10):** retrieval-only attribution F1 over a
50-contract / 50-question CUAD subset, same embedder (`all-MiniLM-L6-v2`) on
both sides, top-k = 5. The only structural difference between the two systems
is chunking: Nexum splits on paragraph boundaries via `parseText`, vanilla RAG
uses fixed 1024-character chunks (the LlamaIndex default).

| Metric | Nexum | Vanilla RAG | Delta |
| --- | --- | --- | --- |
| Attribution F1 | 0.0133 | 0.0067 | +0.0067 |
| Precision | 0.0080 | 0.0040 | +0.0040 |
| Recall (correct doc cited) | 0.1000 | 0.0800 | +0.0200 |

**Status: FAILED.** Nexum out-performs vanilla RAG directionally on every
metric, but the +0.7pp attribution-F1 delta is well below the +5pp G2 pass
criterion. Both systems perform poorly in absolute terms because (a) CUAD's
boilerplate question template ("Highlight the parts (if any) of this contract
related to ...") semantically dominates over the topic token, and (b)
all-MiniLM-L6-v2 is a generic embedder not tuned for legal language. The
result is honest evidence that paragraph-block chunking alone does not deliver
the wedge — the typed-link layer (structural links + AI links) was not yet
populated for this run because the embed/structural-link workers are not
auto-started in the API server. A follow-up run with the link layer wired in
would test whether graph traversal closes the gap.
